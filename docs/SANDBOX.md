# 系统隔离

默认 `managed` 模式进行业务观察、进程管理及 Guard 自保护，但不提供操作系统权限隔离。`os-sandbox` 为整个受控 Yunzai 工作进程及其后代增加操作系统限制；按插件选择的独立隔离另见[独立插件沙箱](NATIVE-PLUGIN-SANDBOX.md)。

## 配置

在面板保存以下设置会协调重建业务进程；手工合并到 `data/yunzai-guard/settings.json` 时，仍需完整重启宿主：

```json
{
  "isolationMode": "os-sandbox",
  "sandbox": {
    "network": "none",
    "writablePaths": ["data", "temp", "logs", "config/config"]
  }
}
```

示例沿用默认运行目录。网络 `none` 阻止直接网络连接，使用网络协议的业务需要明确选择 `host` 并评估服务端权限；`host` 不限制目的地址。审计规则的允许或记录动作不能扩大系统权限。

`writablePaths` 使用项目内相对路径，最多 32 项。核心、插件源码、依赖和 Git 目录不能作为额外可写范围；Guard 控制目录始终受保护。路径、链接、文件类型和平台能力在启动时再次校验，不能通过字符串配置绕过系统检查。

Linux 默认优先使用系统 bubblewrap，缺失时自动校验并使用随插件提供的静态副本；也可通过 `sandbox.bwrapPath` 指定绝对可执行路径。显式路径无效或不具备所需系统能力时明确失败，不自动退回 `managed`。`dist/cli.js doctor` 可提前准备当前配置需要的组件。

## 平台行为

| 平台    | 文件与网络边界                                                                          | 回收方式                                            |
| ------- | --------------------------------------------------------------------------------------- | --------------------------------------------------- |
| Linux   | bubblewrap 命名空间、只读核心和依赖、明确可写目录、seccomp；`none` 使用独立网络命名空间 | 等待受控 PID 命名空间结束，覆盖脱离普通进程组的后代 |
| Windows | AppContainer、专用文件权限和完整性标签；`none` 不授网络能力                             | 不可 breakaway 的 Job Object，结束后撤销会话权限    |

Linux 依赖所需的 user、mount、PID、IPC、UTS 等命名空间和系统调用能力，发行版安全策略可能限制它们；随包程序不会更改系统权限或启用 setuid。Windows 辅助程序已预编译并随包校验，无需安装 C# 编译器，仍需系统 PowerShell、.NET Framework 运行环境及可用 AppContainer。macOS 不支持。

Windows `host` 网络能力不会自动添加系统 loopback 豁免，因此不能据此保证连接宿主 Redis 等本机服务。外部 Node 路径和依赖解析也需通过平台检查，不能为兼容而扩大系统根目录权限。

## 启动与退出

每代实例先建立运行描述和独立审计通道，再启动业务入口。审计通道只接受限定的注册和事件，不授予停止宿主、修改配置等管理能力。

可写文件系统范围会检查符号链接、reparse point 和硬链接，避免通过别名改写只读文件。Windows 会话使用 Node 副本，不修改原 Node 或系统目录权限；插件沙箱允许的 pnpm 依赖链接另有更细限制。

宿主确认整个系统范围退出后才允许下一代启动。Windows 撤销会话权限可能涉及目录遍历；权限回收不能确认时保留恢复证据并停止重建。外层 PM2 或 systemd 应提供足够停机期限，强杀不能作为清理成功的证明。

## 限制

- 系统隔离共享宿主内核，未实现统一的 CPU、内存、进程数与存储配额。
- 只读项目挂载防止写入，不会隐藏全部项目内容或业务秘密。
- Worker、可确认的 Node 子进程可传播 JS 监控；Shell、非 Node 程序与原生扩展内部不提供逐 API 审计。
- Guard 自保护固定拒绝已覆盖入口的文件与函数修改；既有句柄、硬链接、并发路径替换及直接系统调用等情况仍需系统隔离约束，不能仅凭 JS 检查宣称无条件防篡改。
- 审计失败或丢失不等于系统权限失效，也不能据此保证所有被系统拒绝的操作都有日志。
- 首次普通插件加载仍有接管前盲区，需要早期覆盖时使用显式 launcher。

配置前先确认[运行要求](ENVIRONMENTS.md)及[安全边界](../SECURITY.md)。维护与卸载按[生命周期指南](LIFECYCLE.md)确认权限回收后进行。
