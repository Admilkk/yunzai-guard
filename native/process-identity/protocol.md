# Native process identity protocol 1

The executable receives **no command-line arguments**. The trusted Host starts its own
ChildProcess with private stdin/stdout/stderr. One helper has exactly one role/session.
It does not read an arbitrary path, select a signal supplied by a caller, or listen on
network sockets. Source is private testing code; host trust does not extend to hostile
same-user administrators.

Each UTF-8 JSON object occupies one line, including the newline at most 65536 bytes.
Reject duplicate keys, unknown keys, malformed/extra frames, non-ASCII protocol tokens,
more than 64 requests, or more than 256 captured records. Stderr is at most 65536 bytes.
Integers use exact JSON positive integers up to 2147483647 for PID/budget and safe positive
request IDs. Native birth/time fields remain bounded decimal strings, never JS Numbers.

Every request contains exactly these common fields:

```
protocol: 1
sessionNonce: 48 lowercase hexadecimal characters (Host randomBytes(24), first frame)
requestId: positive, strictly increasing safe integer
remainingBudgetMs: positive integer, <= 2147483647
command: one of the commands below
```

The first request fixes the session nonce. All replies echo protocol/sessionNonce/requestId.
The first open request has `sessionBudgetMs`; native uses a monotonic absolute deadline
from the first frame. Later frames may only shorten that deadline. Native always uses
`min(initialDeadline, now + remainingBudgetMs)`. There is **no 120-second session cap**:
a caller can budget capture12s + configured shutdown120s + force5s and overhead. Host also
keeps its original absolute deadline from before spawn; subsequent requests never renew it.
Before the first frame a 10-second bootstrap read bound is allowed; EOF closes resources.
After open, stdin reads/native waits use the same session deadline. No side effect starts
after deadline. Protocol/EOF/deadline errors release only this helper's descriptors.

| command | Additional request fields | Required state |
|---|---|---|
| open-root | rootPid, sessionBudgetMs | new; Windows only; root is caller's actual direct child |
| capture-root | rootBindingToken, hostProbeSerial | root-held; same already-open root HANDLE |
| terminate-captured | rootBindingToken, recordIds | root-held/captured; only earlier internal record IDs |
| open-inspector-parent | sessionBudgetMs, optional expectedParent | new; target comes from actual helper parent app's parent |
| activate-inspector-once | parentBindingToken | parent-held, activationAvailable true, never attempted |
| confirm-inspector-parent | parentBindingToken, connectionSerial | parent-held/action-completed; fresh serial increasing |
| close-session | none | any; closes this session only |

Tokens generated by native are 32 lowercase hex characters. `expectedParent` is a native
identity object, not legacy CIM timestamp or caller-selected target. It can only compare
against the native-selected actual parent:

```
{ pid, birth: {kind:"windows-filetime-100ns",value:"..."} }
{ pid, birth: {kind:"linux-proc-start-ticks",value:"...",bootId:"UUID",pidNamespace:"dev:ino"} }
```

Replies have the following additional fields (closed schemas):

* `root-ready`: rootBindingToken, root, caller, nativeRelation:"caller-direct-child".
  Native opens only root QUERY/SYNCHRONIZE here, no descendant census/HANDLEs.
* `root-captured`: rootBindingToken, root, captureSerial, records, observation
  ("complete"|"incomplete"), unknownCount. Each record is `{recordId,identity,parentPid}`.
  Validate root/duplicates/each birth edge before opening candidate query HANDLEs. Each
  opened candidate gets full GetProcessTimes FILETIME and is held for later fixed action.
* `captured-terminated`: rootBindingToken, results. Each result is
  `{recordId,result, optional systemCode}`; result is original-exited,
  terminated-and-exited, identity-changed, unknown. Same held HANDLE query/kill/wait.
* `inspector-parent-ready`: parentBindingToken, caller, parent, activationAvailable,
  optional activationProfile, optional unavailableReason. The profile is
  `{id,platform,architecture,verification:"qualified-target-image",inspectorActivation}`.
  Activation is windows-held-handle-debug-mapping or
  linux-held-pidfd-sigusr1-under-trusted-stable-handler. The actual target image must
  qualify; app Node version never qualifies a different daemon.
* `inspector-activated`: parentBindingToken, actionSerial, originalParent, result
  ("native-action-completed"|"started-unconfirmed"). Accepted signal/completed remote
  thread does not mean an endpoint is ready. Any attempt consumes the single action.
* `inspector-parent-confirmed`: parentBindingToken, connectionSerial, parent,
  originalLive:true. Host sends a new serial only after its specific WS establishes.
* `session-closed`: released:true.
* `refused`: result ("refused-before-action"|"failed"|"started-unconfirmed"|"unknown"),
  code, optional systemCode. No raw environment, paths, commandline or stack is output.

Refusal codes: UNSUPPORTED_PLATFORM_OR_ARCH, UNSUPPORTED_NODE_PROFILE,
NATIVE_PRIMITIVE_UNAVAILABLE, ACCESS_DENIED, ROOT_OR_PARENT_CHANGED, IDENTITY_UNKNOWN,
RELATIONSHIP_UNKNOWN, SIGNAL_HANDLER_UNAVAILABLE_OR_UNKNOWN, INSPECTOR_ACTIVATION_DISABLED,
ACTIVATION_ALREADY_ATTEMPTED, STATE_OR_REQUEST_INVALID, FRAME_OR_SCOPE_LIMIT, DEADLINE,
NATIVE_OPERATION_UNKNOWN.

Windows binds caller/root/parent from real native relations and full GetProcessTimes.
The helper holds the same parent HANDLE through PE/profile verification, mapping, and
CreateRemoteThread. Mapped-image PE machine/version resource (or equivalent same-HANDLE
qualification) is required: disk FileVersionInfo alone is insufficient. Initial profile
is x64 Node24.22.1 only. This Windows gate checks the held target's mapped PE64/version
resource and that the debug mapping handler is in executable MEM_IMAGE pages. It is a
trusted-target layout/version gate, not a complete official-image SHA or proof against
forged version resources. The Host's separate original ProcessWrap native0 probe pins
its own official executable SHA; that does not qualify a different daemon's full bytes.
No privilege changes, Python, ptrace or numeric action fallback.

Linux uses a held pidfd plus anchored proc/image/namespace descriptors, exact start ticks,
actual getppid chain and actual daemon image SHA. The only x64 Node24.22.1 images are:

| Actual held daemon ELF SHA256 | Fixed profile id |
|---|---|
| 569128f3066ac7be59b10b9a0adef708def642ee37cbf9d560a9bdb68f872108 | node24.22.1-linux-x64-musl-569128 |
| e32e2d16081cf644f88392934288086e7662529d0d43277c34f7aad2207cfafb | node24.22.1-linux-x64-glibc-e32e2d |

Both select through the same held executable fd/full hash and unchanged-file checks;
there is no version/path-only fallback. The glibc image is the official linux-x64
archive binary (glibc>=2.28), separately qualified on Ubuntu24.04 with its actual
loader/libraries, owned parent SIGUSR1, exact WS target PID and fresh native confirms.
That container qualification is not systemd/VM/PM2/business or host-reboot acceptance.
Changing the table still requires qualification of the final rebuilt helper in both
environments; a private single-image candidate does not qualify a later binary.
Only the target SIGUSR1 macro is used. Current caught/ignored/blocked/pending state and
visible disabling NODE_OPTIONS tokens gate new activation. Environ is bounded and only
a disable enum is output; unknown refuses. PM2 process.title can destroy original argv,
so cmdline never claims complete flags. SigCgt is not proof of the Node handler; the
explicit trusted daemon stable-handler/no-concurrent-exec model is retained. Unknown
profiles/dispositions refuse new activation. Existing endpoint binding need not activate.

The TS root adapter pins original ChildProcess ProcessWrap receiver/method before await.
It executes original native0 -> open-root -> original native0 -> capture-root -> original
native0 -> complete schema/root validation -> synchronous ledger commit. It never calls
public child.kill(0) and never probes after a termination request; session closes on loss.

## Bundle manifest and maintainer build

`native/process-identity/manifest.json` schema1 has `protocol:1`, `sources` (relative file
SHA256), `artifacts` and `builds`. An artifact is exactly
`{platform,architecture,file,sha256,bytes,format}` (win32/x64/pe-framework or
linux/x64/elf-static). Paths are package-relative under `bin/`, regular non-linked files.
The native program embeds its fixed profile set; no request supplies a profile/path.
Manifest also includes `profileSet:"node24.22.1-v1"`. Build metadata records source,
compiler path/version/hash, arguments, target and output hash, not secrets.

`scripts/build-process-identity.mjs` defaults to verifying shipped prebuilt artifacts.
Only explicit `--build --output <fresh-ignored-directory>` compiles, using existing
Framework64 csc with /platform:x64 /r:System.Management /r:System.Web.Extensions and
existing pinned Zig0.16.0, with both Zig caches under that output. No download/install.
It never writes shared dist/production bin; root's final build copies the reviewed
bundle. The separate fixture-only C reclaimer is not a production protocol command.
